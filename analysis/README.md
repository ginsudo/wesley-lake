# analysis/ — two kinds of thing, kept apart on purpose

They used to sit in one directory, which was a standing data-loss risk: a
reasonable person clearing `analysis/*` to force a rebuild would have destroyed
every observation record in the project.

## `derived/` — SAFE TO DELETE

Regenerated by `python3 pipeline/run.py` in a few minutes.

- `*-candidates.json` — detector output, one record per box
- `exif-index.csv`, `session-index.md` — rebuilt from `photos/`

Git-ignored. Delete the whole directory whenever you like.

## `records/` — NEVER DELETE

**Human judgement. Nothing can regenerate it.** Every species call, every count,
every stratum and surface assignment, every water assessment — each one came
from someone looking at a native-resolution crop and deciding.

- `*-observations.json` — bird records (`pipeline/schema.py`, v3)
- `*-water.json` — water records (`pipeline/water.py`, v2)
- `*.md`, the per-session write-ups and the season rollup

In git, and it is the reason this project is in git at all.

## The rule

If you are unsure whether something is safe to delete, the answer is in which
directory it is in. If it is in neither, do not delete it.
